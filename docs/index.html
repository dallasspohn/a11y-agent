How It Works

Detection Pipeline (Deterministic)

1

Static Lint

Parses HTML, checks missing alt text, invalid ARIA, heading order — ~100ms

2

Browser Scan

Playwright + axe-core checks computed styles, contrast, focus order — ~2-5s

3

AI Explains

Generates WHY it matters, the before/after edit, and WCAG criterion

4

Validate & Apply

Edits verified against real source, .bak backup, re-scan confirms

Key Design Decisions

Detection is deterministic, AI only explains. Violations are found by lint.js and axe-core — AI is only used for fix suggestions and explanations, never detection.

Applied fixes are validated, not trusted. generateFixPlan() asks the model for one structured JSON edit per violation. Edits whose before strings aren't found exactly are marked manual. Every write makes a .bak and is followed by a verification re-scan.

Voice Layer (Accessibility for the Tool Itself)

Input: Vosk STT, toggled with SPACE, fully offline
Parsing: Natural language → CLI flags, or → violation indices for fix selection
Output: edge-tts neural voice (espeak fallback) reads violations, fixes, and summaries
Loop: Selection → fixes → apply → verify → renumbered list → repeat

Automation Layer (Shift Left)

watch.js monitors file changes, auto-runs lint on save.
Pre-commit hook blocks git commits if serious violations found.
GitHub Actions runs scan on every PR, blocks merge if violations exceed threshold.

The James Persona Story

James is a visually impaired developer at Red Hat. When he needs to test accessibility of a product interface, he currently needs a sighted colleague to open dev tools, run axe DevTools, read violations aloud, Google fixes, and describe the code.

With A11Y Agent + Voice:

  1. James runs a11y-agent and hears "Agent at the ready"
  2. He says "scan bad page" — the tool speaks the summary and reads a numbered list
  3. He says "fix all critical" — the tool generates and reads the fixes
  4. He says "yes" — the file is patched, with a backup
  5. The tool re-scans and confirms: "1 of 1 selected issue resolved. 7 violations remain."
"We built an accessibility testing tool... and then made it accessible. Because if James can't use our accessibility checker, what's the point?"

Known Issues

  • Auto-fix quality varies by rule. image-alt and html-has-lang are reliable. Structural rules can produce edits on local llama3.1 that introduce new violations. Review the diff before accepting.
  • Fix generation is slow locally — roughly 30s per violation on llama3.1. Select one or two issues during a live demo.
  • select-name reliably produces no automatic edit — the tool reports it as needing a human, which is correct behavior.
  • Auto-apply only works on local files, not URLs.
